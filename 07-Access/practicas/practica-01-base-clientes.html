Práctica #01

Migración de Excel a Access — bdTienda y bdFarmacia

Importa bases en Excel, crea el modelo relacional en Access y luego arma formularios

Objetivo

Migrar dos bases de datos de Excel a Microsoft Access mediante importación, definir claves primarias/foráneas y relaciones, y dejar el .accdb listo para construir formularios en la siguiente fase.

Archivos Base (Excel)

Descarga los dos libros que contienen datos normalizados listos para importar. No los edites en Excel — el trabajo principal se hace en Access.

📥 Descargar bdTienda-v1.xlsx 📥 Descargar bdFarmacia-v1.xlsx
Contenido de cada libro
  • bdTienda-v1.xlsx: 4 hojas — VENDEDOR (10), PRODUCTO (50), VENTA (300), DETALLE_VENTA (906)
  • bdFarmacia-v1.xlsx: 4 hojas — EMPLEADO (10), MEDICAMENTO (50), VENTA (300), DETALLE_VENTA (907)

Ambas bases comparten el patrón VENTA → DETALLE_VENTA (1 a N) y catálogos maestros. Ideal para practicar claves y relaciones idénticas en dos dominios distintos.

Flujo de Migración (Excel → Access)

1. Crear la base destino

Access → Base de datos en blanco → guarda como Tienda_Migracion_TuNombre.accdb y Farmacia_Migracion_TuNombre.accdb (una base por cada Excel).

2. Importar cada hoja como tabla

Por cada hoja: Datos externos → Nuevo origen de datos → Desde archivo → Excel → selecciona el .xlsx → Importar el origen de datos en una nueva tabla de la base de datos actual → marca Primera fila contiene encabezados.

  • En el asistente, respeta los nombres: VENDEDOR / PRODUCTO / VENTA / DETALLE_VENTA (o EMPLEADO / MEDICAMENTO / VENTA / DETALLE_VENTA).
  • Define tipos: Id* como Número entero largo (luego será PK/FK), PrecioUnitario/PrecioVenta como Moneda, Fecha como Fecha/Hora, Stock* y Cantidad como Número.
  • No dejes que Access cree un campo Id automático si ya existe IdVendedor/IdProducto/etc. — elige Elegir mi propia clave principal y selecciona el Id correspondiente.

3. Definir claves primarias

En Vista Diseño de cada tabla, asigna la llave (clic derecho → Clave principal):

BaseTablaClave principal
TiendaVENDEDORIdVendedor
TiendaPRODUCTOIdProducto
TiendaVENTAIdVenta
TiendaDETALLE_VENTAIdDetalle
FarmaciaEMPLEADOIdEmpleado
FarmaciaMEDICAMENTOIdMedicamento
FarmaciaVENTAIdVenta
FarmaciaDETALLE_VENTAIdDetalle

4. Crear relaciones e integridad referencial

Herramientas de base de datos → Relaciones → agrega las 4 tablas → arrastra:

  • Tienda: VENDEDOR.IdVendedor → VENTA.IdVendedor, VENTA.IdVenta → DETALLE_VENTA.IdVenta, PRODUCTO.IdProducto → DETALLE_VENTA.IdProducto
  • Farmacia: EMPLEADO.IdEmpleado → VENTA.IdEmpleado, VENTA.IdVenta → DETALLE_VENTA.IdVenta, MEDICAMENTO.IdMedicamento → DETALLE_VENTA.IdMedicamento

En cada relación tilda Exigir integridad referencial y Actualizar en cascada los campos relacionados. Verifica arrastrando un IdVendedor inexistente en VENTA — Access debe rechazarlo.

5. Siguiente fase: formularios

Con el modelo migrado y relacionado, en la próxima clase construirás formularios (ej. formulario VENTA con subformulario DETALLE_VENTA) para carga operativa sin tocar las tablas directamente.

Entregable
  1. Dos archivos: Tienda_Migracion_TuNombre.accdb y Farmacia_Migracion_TuNombre.accdb con las 4 tablas importadas, PK definidas y relaciones con integridad referencial.
  2. No se requiere aún formulario — quedará para la práctica 02.
  3. Sube los .accdb a la plataforma o envíalos según indique el docente.
Dónde están los descargables

Los Excel viven en 07-Access/practicas/archivos/ y se enlazan como archivos/bdTienda-v1.xlsx (relativo a esta práctica). Para agregar nuevos recursos, súbelos a esa misma carpeta y añade un <a download> aquí.
